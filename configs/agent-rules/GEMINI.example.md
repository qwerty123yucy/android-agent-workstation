# PRoot + Termux 手机工作站全局约束模板（`~/.gemini/config/GEMINI.md`）

## 运行环境约定
- **PRoot 无嵌套本地沙箱**：当前运行在 Termux PRoot 容器内，不支持嵌套 `fork/exec` 内核沙箱（会固定返回 `operation not permitted`）；若命令执行工具提供沙箱开关则跳过本地沙箱试错。
- **宿主机真机 ADB**：原生 Termux 通过 `127.0.0.1:5037` 共享本机无线 ADB（目标 `127.0.0.1:5555`）。安全与故障边界：
  - 未经用户明确同意，不得对宿主机截屏、读取界面、拉起应用或注入输入；
  - 真机操作仅限当次授权的目标包名，涉及对外发消息/删除个人数据/交易变更前必须确认；
  - 所有命令显式带 `-s 127.0.0.1:5555`（避免 `emulator-5554` 双设备号冲突）；若断连最多尝试一次 `adb connect 127.0.0.1:5555`，严禁在 PRoot 内执行 `adb kill-server` 或无线 `adb pair`，仍不通时通知用户回原生 Termux 处理。
- **真实渲染与边界验证**：涉及前端、Canvas、WebView 或原生 Android 界面布局时，交付前在目标真实视口下经真实渲染环境（Web/WebView 用 `chromium-headless-shell --use-gl=disabled`，获授权的原生 App 用宿主机真机 ADB）完成包围盒重叠/截断检测与截图目视核验。
- **禁止自启动交互式 Agent**：任何情况下不得在工具或子进程中自行执行全屏交互式 `agy` 命令。

## 执行流与失败收敛
- **短操作一步到位，长任务防 STALL**：预计十几秒内的命令设足够同步等待窗口；大文件传输或长构建转后台并配合超时检查，禁止 shell `sleep` 盲轮询。
- **结果重于退出码**：退出码 `0` 不替代实际状态验证（配置、构建、同步或安装后须核验最终产物/MD5/运行态）。
- **单次重试上限**：真正的环境或命令报错最多针对性重试一次，仍失败则保留现场并汇报原因。
- **上下文克制原则**：全局规则仅保留跨项目硬约束，通用工具链细节放按需加载的 Skills，单仓库构建细节留在项目本地 README/脚本。
